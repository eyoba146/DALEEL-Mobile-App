# DALEEL UI Redesign Plan

## 1. Redesign Objective

This redesign is a major visual transformation of the existing DALEEL application.

The goal is NOT to make the current interface slightly cleaner.

The goal is to create a substantially new, cohesive, professional mobile UI while preserving the approved DALEEL product functionality, navigation, and data behavior.

The application should look noticeably different after the redesign.

A user comparing the old and new versions should immediately recognize that the visual system and screen composition have been significantly redesigned.

The redesign must preserve the product's existing purpose and functionality.

Do not turn this into a product rewrite.

---

## 2. Core Brand Identity

DALEEL uses:

- Deep Navy: #07152B
- Warm Gold: #DFB76C
- Off White: #F7F8FA

Hierarchy:

Deep Navy = PRIMARY
Warm Gold = ACCENT
Off White = MAIN BACKGROUND

Deep Navy should provide the main structural identity of the application.

Warm Gold should be used deliberately and sparingly.

Off White should provide the majority of the light canvas and breathing space.

Do not make Warm Gold the dominant visual color.

Do not turn the application into a dark-mode product.

Do not replace the brand palette with unrelated colors.

---

## 3. Design Philosophy

The design should feel:

- Professional
- Premium
- Modern
- Refined
- Trustworthy
- Calm
- Distinctive
- Mobile-first
- Internationally polished
- Ethiopian in identity without relying on stereotypes

The design should not feel:

- Template-like
- Overdecorated
- Gold-heavy
- Generic
- Like a collection of cards
- Like a dashboard template
- Like an AI-generated component library
- Like a tourism-only application
- Like a financial trading application
- Like a conventional e-commerce storefront

The design should rely on hierarchy, composition, typography, imagery, spacing, and controlled color rather than decoration.

---

## 4. Major Visual Transformation Requirement

Every primary screen must receive a meaningful visual re-composition.

Do not simply:

- change colors
- adjust border radius
- add shadows
- change button colors
- change typography slightly
- convert one card style into another

Those changes are necessary only when they support the larger redesign.

Instead, rethink:

- composition
- section hierarchy
- density
- image placement
- grouping
- content rhythm
- navigation treatment
- spacing
- typography relationships
- primary action hierarchy
- visual entry points
- transitions between sections

The redesigned application should be visibly different even before a user interacts with it.

---

## 5. Global App Shell

Create a new cohesive visual shell for the application.

The shell should establish the DALEEL identity immediately through:

- Deep Navy structural elements
- restrained Warm Gold accents
- Off White content canvas
- strong typography hierarchy
- refined spacing
- consistent iconography
- sophisticated surface treatment

The shell should provide a strong visual relationship between:

- header
- content
- navigation
- floating actions where appropriate
- status/safe areas
- section transitions

Do not use the same visual treatment for every screen.

---

## 6. Sidebar / Side Panel Direction

Where an existing sidebar, drawer, or side-navigation surface exists, use:

Deep Navy (#07152B) as the full sidebar background.

The sidebar should feel like a strong branded surface.

Use:
- White or Off White primary text
- restrained Warm Gold for active indicators
- subtle transparency or tonal changes for secondary states where appropriate
- clear selected-state hierarchy
- consistent icon treatment

The sidebar should not become visually cluttered.

Do not add a new navigation system solely to create a sidebar.

Existing navigation destinations and approved navigation architecture remain unchanged.

---

## 7. Mobile Navigation

Preserve the approved mobile navigation:

Home
Explore
Services
Saved
Profile

Do not add or remove tabs.

However, completely redesign the visual treatment of the navigation.

The navigation should feel integrated into the new visual system rather than looking like a generic tab bar.

Use Deep Navy as the primary navigation identity.

Use Warm Gold only as a controlled active-state accent.

---

## 8. Home / Dashboard

Home must receive one of the largest visual transformations.

Do not preserve the current page structure simply with improved cards.

Recompose the screen around a clear editorial and personalized hierarchy.

The design should make the user immediately understand:

- who DALEEL is for
- what matters now
- what DALEEL recommends
- where the user can explore next

Use the existing Home data and functionality but rethink its visual composition.

Potential design directions may include:

- stronger hero/greeting area
- more deliberate personalized content hierarchy
- larger editorial feature
- modular but visually unified discovery sections
- stronger visual transitions between content categories
- better use of image scale
- stronger primary search treatment

The exact composition is left to the designer after inspecting the existing application.

The important requirement is that Home must look substantially redesigned.

---

## 9. Explore

Explore should feel like a premium discovery experience.

Recompose the page instead of simply changing card styling.

Improve:

- category hierarchy
- destination discovery
- visual storytelling
- search entry
- filtering
- featured content
- article discovery
- place discovery

Use different visual weights for important and secondary content.

Avoid turning Explore into an endless uniform grid.

---

## 10. Services

Services should feel like a trustworthy professional directory.

Reconsider:

- provider hierarchy
- service category presentation
- verified state
- location
- service description
- primary contact/action hierarchy

Use stronger visual distinctions between:

- service category
- provider
- service offering
- supporting information

The page should not feel like a list of generic marketplace cards.

---

## 11. Saved

Saved should be redesigned around organization and usefulness.

Reconsider the visual relationship between different saved content types.

The user should be able to immediately understand what has been saved and why it matters.

Create a strong visual hierarchy for:

- saved services
- saved events
- saved products
- saved investments
- saved articles

Use thoughtful empty states rather than simple blank screens.

---

## 12. Profile

Profile must receive a complete visual redesign.

Do not leave it as a conventional settings list.

Create a stronger hierarchy around:

- identity
- country
- language
- user type
- interests
- notifications
- security
- account controls

The top profile area should feel like a designed product surface.

Settings should be organized into clear visual groups rather than a long undifferentiated list.

---

## 13. Events

Recompose Events into a strong discovery experience.

Consider:

- event imagery
- date hierarchy
- event category
- location
- save action
- event information density

The event listing and detail pages should feel related but not identical.

Do not introduce booking, ticketing, or payment functionality as part of this redesign.

---

## 14. Investment

Investment must look informative, credible, and professional.

It must NOT visually resemble:

- a trading terminal
- a brokerage
- an investment execution platform
- a payment product

Focus the design on:

- opportunity discovery
- informational content
- guides
- resources
- categories
- save/search actions

Do not introduce investment execution UI.

---

## 15. Marketplace

The Marketplace should be visually polished but still respect the approved MVP request-based model.

Improve:

- product discovery
- product hierarchy
- imagery
- seller/business presentation
- categories
- favorites
- request action

Do not introduce:

- shopping cart
- bag
- checkout
- payment
- shipping
- vendor payouts

A product should lead naturally to its approved request flow.

---

## 16. Detail Pages

All detail pages should share a strong visual language without becoming identical.

Recompose:

- hero imagery
- title hierarchy
- metadata
- primary action
- supporting information
- related content
- save action
- verified state
- content sections

Different content types should have different compositions appropriate to their purpose.

---

## 17. Authentication and Onboarding

Redesign onboarding and authentication to match the new visual identity.

The experience should feel polished before the user even reaches Home.

Reconsider:

- illustration/image placement
- typography scale
- progression
- form composition
- primary action hierarchy
- field grouping
- background treatment

Do not expand authentication functionality beyond the approved product scope.

---

## 18. Search

Search should feel like a major product capability rather than a utility field.

Recompose:

- search entry
- suggestions
- categories
- filters
- recent searches
- result hierarchy
- empty results

Make discovery feel fast and intentional.

---

## 19. Notifications

Redesign the notification center using the new visual language.

Create clear hierarchy between:

- important updates
- request/order updates
- promotional content
- other supported notifications

Do not add push/email/SMS infrastructure.

---

## 20. Loading, Error, Empty, and Offline States

These states should receive the same visual attention as the primary screens.

Create a coherent family of:

- loading states
- skeletons
- empty states
- error states
- retry states
- offline states
- success states
- confirmation states

Do not make these feel like developer placeholders.

---

## 21. Typography

Create a strong typography system.

Use hierarchy rather than oversized text.

The typography should work naturally with:

- English
- Amharic
- long titles
- metadata
- buttons
- navigation labels
- cards
- detail pages

The typography system should contribute significantly to the new visual identity.

---

## 22. Imagery

Use imagery as a major part of the redesigned composition.

Improve:

- image scale
- cropping
- visual hierarchy
- aspect ratios
- placement
- relationship between image and typography

Do not treat imagery as something placed inside generic cards.

Images should help define each screen's composition.

---

## 23. Cards and Surfaces

Do not use one universal card style everywhere.

Create a small family of intentional surface patterns.

Some content may use:

- open editorial layouts
- compact list rows
- elevated surfaces
- image-led compositions
- featured panels
- compact information blocks

Choose the pattern based on content importance.

Avoid turning every content type into the same rounded rectangle.

---

## 24. Buttons and Actions

Create a strong action hierarchy.

Primary:
Deep Navy

Accent:
Warm Gold when genuinely appropriate

Secondary:
subtle supporting treatment

Use clear interaction states.

Do not allow secondary actions to visually compete with primary actions.

---

## 25. Color Usage

Deep Navy should dominate primary structural and interactive moments.

Warm Gold should appear as an accent.

Off White should provide the main visual breathing space.

Use semantic colors only where required for:

- success
- warning
- error
- informational feedback

Avoid random color usage.

---

## 26. Motion

Use restrained motion to support:

- navigation
- transitions
- save actions
- expansion
- confirmation
- loading

Do not add animation simply to make the application feel busy.

---

## 27. Responsive Mobile Quality

The redesign must work across real mobile sizes.

Check:

- safe areas
- smaller displays
- long text
- Amharic text
- keyboard
- touch targets
- scrolling
- image cropping
- bottom navigation
- content density

---

## 28. Accessibility

Maintain practical accessibility:

- contrast
- labels
- touch targets
- readable typography
- non-color-only communication
- English readability
- Amharic readability

Do not claim formal certification.

---

## 29. Product Scope Protection

The redesign must not introduce product functionality that is outside the approved DALEEL MVP.

Do NOT add:

- shopping cart
- bag
- checkout
- payments
- shipping
- vendor payouts
- provider portal
- provider login
- provider analytics
- self-service KYC
- live news
- government transaction portal
- remittance transaction system
- investment execution
- telehealth
- government e-services
- advertising network
- push/email/SMS infrastructure
- map product
- ML recommendation system
- unrelated modules

This is a visual transformation of the existing product.

---

## 30. Important Existing-Implementation Audit

Before redesigning, inspect the current repository and identify features previously introduced that conflict with the approved DALEEL MVP.

Do not blindly preserve newly introduced out-of-scope features.

Examples to audit include:

- map SDK/UI
- direct WhatsApp actions
- booking flows
- pass/ticket flows
- shopping bag/cart
- Add to Bag actions
- investment execution-like actions
- email verification
- unapproved password reset flows

If these were introduced by a previous redesign and are not part of the approved MVP, remove or revert those UI/functionality additions as appropriate while preserving the legitimate underlying application functionality.

Do not remove unrelated pre-existing functionality without verification.

---

## 31. Major Redesign Quality Gate

The redesign is NOT considered successful if the changes are primarily:

- color swaps
- token changes
- minor spacing changes
- border-radius changes
- button recoloring
- shadow adjustments

Success requires visible transformation of:

- screen composition
- hierarchy
- navigation treatment
- typography
- imagery
- content grouping
- spacing
- surface relationships
- primary-action placement
- overall visual identity

The result must be noticeably different.

---

## 32. Final Design Goal

DALEEL should feel like:

A serious, premium, modern mobile product with a strong Ethiopian identity and an international standard of visual polish.

The final visual hierarchy is:

DEEP NAVY = PRIMARY
WARM GOLD = ACCENT
OFF WHITE = MAIN BACKGROUND

The designer has freedom to determine the best individual layouts after inspecting the current implementation.

The plan defines the quality bar and design direction, not an exact pixel-by-pixel layout.
